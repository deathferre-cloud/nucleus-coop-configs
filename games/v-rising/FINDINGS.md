# Находки V Rising

Проверки на исходном компьютере: 30-31 октября 2026. Здесь нет сырых журналов, персональных идентификаторов или сохранений. Исправление конкретного пункта не заменяет проверку всего игрового сценария. Итоговый сценарий двух игроков и нормального save/reload завершён успешно.

| ID | Что обнаружено | Исправление, проверка и урок |
| --- | --- | --- |
| VR-001 | Jint записывал пустые массивы ActionWheel как объекты. V Rising отвергала ClientSettings и загружала defaults. | Newtonsoft.Json в VRisingSettings сохраняет массивы, объекты и неизвестные поля. Проверен весь вызывающий блок в настоящем Jint, затем оба клиента. Node.js-теста было недостаточно. |

После WindowMode=3 реальный размер стал 1920×1080 → 1440×810 → 1920×1080. Общая DLL не менялась. Проверять фактические окна, не только команду в логе. |

| VR-005 | Отсутствовал debug-log.txt при DebugLog=False. | Это известное поведение, а не доказательство провала запуска. Проверять отдельные игровые журналы и журнал моста. |
| VR-006 | .NET-тест не смог создать fixture в рабочей папке. | Тот же тест выполнен во временном каталоге. Точная причина файловой ошибки не установлена; не выдаётся за дефект игры. |

| VR-009 | Дочерний private server запускался с обычным Windows persistentDataPath, хотя клиент читал отдельные настройки. | Выборочные junction только двух служебных ID согласовали пути. ID проверены против Steam-аккаунтов, каталоги зарезервированы. Сервер загрузил мир и записал новые автосохранения. Это выборочное перенаправление, не полная изоляция процесса. |
| VR-010 | Первая private-game попытка дала «Нет ответа», хотя позже сервер завершил старт. | Первопричина не доказана. Проверенный рабочий сценарий использует SteamIPv4 и выключенную галочку LAN-сервер. Не записывать LAN=True как обязательное условие. |
| VR-011 | При переносе только файлов пропала пустая .TEMP. После чтения autosave сервер намеренно завершился с DirectoryNotFoundException. | Папка восстановлена из копии, сервер загрузился и записал новые autosave. Копировать всё дерево, сверять каталоги отдельно от хешей файлов. |
| VR-012 | После аварии один клиент около восьми минут оставался на «Подключение» без нового ConnectionUpdate. | Чистый запуск Nucleus и обоих клиентов восстановил вход в неизменённый мир. Внутренняя причина остаётся гипотезой. Мир удалять не потребовалось. |
| VR-013 | Синтетический Esc инструмента не открывал меню в gameplay. | Пользователь открыл меню физическими геймпадами и штатно вышел. Это ограничение метода управления инструментом; поломку физического ввода из него не выводим. |

## Итоговая проверка

Оба игрока находились в одном мире, раздельные геймпады и звук подтверждены пользователем. Ctrl+F10 проверен после явного End: wasLocked=True, nowLocked=False, затем восстановлены оба окна. После обычного выхода Player2, затем Player1 сервер прочитал последнее автосохранение, а оба клиента получили существующих персонажей без повторного создания. Исходные Steam-настройки сохранили прежний хеш.

## Что осталось за пределами проверки

- Standalone dedicated server, вариант Yes!.
- Физическое переподключение Bluetooth внутри активного сеанса.
- Точная первопричина первой LAN-попытки и зависшего соединения после аварии.
- Полный игровой запуск переносимого пакета на другом компьютере.
